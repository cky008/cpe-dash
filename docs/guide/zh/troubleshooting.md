先看两样东西：控制台页头的**会话状态**，和容器日志 `docker compose logs --tail 100 cpe-dash`。大多数问题的原因都写在这两处。

## 打不开控制台

- **容器在运行吗**：`docker compose ps` 应该显示 `healthy`。显示 `restarting` 时看日志，最常见的原因是 `.env` 里没有 `DATA_ENCRYPTION_KEY`。
- **端口对吗**：默认是 `18384`，看 `.env` 的 `WEB_PORT`。
- **用域名访问时返回 421**：把域名加进 `ALLOWED_HOSTS`。局域网 IP、`*.local`、`*.lan`、`*.ts.net` 不需要添加。
- **数据目录权限**：日志提示 `EACCES` 时，确认 `.env` 的 `PUID` / `PGID` 是 `data/` 的属主。

## 找不到设置码

```bash
docker compose logs cpe-dash 2>&1 | grep "setup code"
```

设置码 24 小时内有效，重启容器会生成一个新的。

## 连不上路由器

在「设置 → 路由器」点「测试连接」，它会说明原因：

| 提示 | 怎么办 |
| :--- | :--- |
| 认不出路由器的品牌 | 烽燧没有从这个地址得到任何它认识的应答，密码没有发出。确认地址是路由器的管理地址（在这台机器的浏览器里能打开登录页），Docker 下检查容器能否访问局域网；都没问题就在「路由器品牌」里手动选择。品牌不在列表里的路由器，烽燧还连不了 |
| 地址不可达 | 确认这台机器能打开路由器的管理地址（华为通常是 `http://192.168.8.1`）；Docker 下检查容器能否访问局域网 |
| 路由器的应答和所选品牌对不上 | 品牌选错了，或者这个型号用了不同的接口。把「路由器品牌」改回「自动识别」再试 |
| 密码错误，剩余 N 次 | 先在浏览器里确认密码，再回来保存。只剩 1 次时，烽燧会要求你勾选确认才再试 |
| 路由器已锁定 | 密码错太多次，路由器锁定了一段时间。等锁定结束后再保存正确的密码 |
| 有人正在登录官方网页 | 在官方网页上退出登录，再测试 |
| 需要先修改密码 | 路由器要求先在官方网页上改一次默认密码 |

<a id="breaker"></a>

## 页头显示「路由器密码错误 · 已停止登录」

路由器拒绝了密码，烽燧立刻停下，避免把路由器锁死（连续输错几次会锁住路由器，华为是 3 次）。到「设置 → 路由器」填写正确的密码并保存：烽燧先测试一次，成功就自动恢复。

<a id="yielding"></a>

## 页头显示「有人在用路由器管理页 · 已暂停」

有人登录了路由器官方网页（可能是你自己在另一台设备上，或者家人）。烽燧会每隔一段时间再看一次，对方退出后自动继续。期间数据停在最后一次读取的值，改动路由器的操作会返回「有人正在使用路由器」。

## 收不到 Telegram 通知

1. 日志里有 `telegram=on` 吗？没有就是 `TELEGRAM_BOT_TOKEN` 不对。
2. 「设置 → Telegram」里列出你的聊天了吗？没有就重新生成绑定码，私聊机器人发送 `/auth 绑定码`。
3. 告警级别够吗？默认只推送 `warning` 及以上（`ALERT_NOTIFY_MIN_SEVERITY`）。
4. 断网期间的通知会暂存，恢复后补发。
5. 同一个机器人令牌只能被一个程序使用。如果别的程序也在用它，两边都会出错。

<a id="write-refused"></a>

## 写操作被拒绝（未验证的路由器）

在 H168-383 以外的路由器上，烽燧只做它为这台路由器实现了的写操作。被拒绝时路由器没有收到任何请求：

| 提示或错误码 | 原因和处理 |
| :--- | :--- |
| 「这项写入已经在『设置 → 设备』关闭」，`DEVICE_WRITE_DISABLED` | 这一项被关掉了。到「设置 → 设备」的「实验性写入」里重新打开 |
| 「烽燧不能在这台路由器上做这项写入」，`DEVICE_UNVERIFIED_READ_ONLY` | 烽燧在这个型号上还没有这项写入的实现，或者路由器不具备它需要的条件（「设置 → 设备」里显示「这台路由器不提供」）。可以在路由器自己的管理页面操作，也欢迎[提交设备报告](other-routers.md#report) |
| 告警 `WRITE_READBACK_MISMATCH` | 写入发出去了，但回读的结果和写入的不一样，路由器可能没有照做。到路由器自己的管理页面核对；这一项不可靠的话，把它关掉并提交报告 |

详见[其他型号与品牌](other-routers.md#writes)。

## 发短信失败

- **提示「No default country is known」**：烽燧还不知道你的国家（路由器没有报告 SIM 卡信息）。输入带 `+` 的完整号码，或在发送界面选择国家，也可以在「设置 → 常规」的「短信」里固定默认国家。
- **显示「已提交、状态未确认」**：短信很可能已经发出，不要重发，稍后在会话里查看。
- **路由器拒绝发送**：检查 SIM 卡余额和短信功能是否开通。

## 时间不对

发出短信的时间、历史曲线的时间都按 `.env` 的 `TZ`。改成你所在的时区（例如 `Asia/Shanghai`），重启容器。

## 数据打不开（DATA_QUARANTINED 告警）

密钥和加密文件对不上。文件没有被删除，只是改名为 `*.unreadable-<时间>`。找回原来的密钥后，按[备份与恢复](backup.md#更换加密密钥)里的 `rekey` 恢复。

## 还是没解决

- 运行自检：`docker exec cpe-dash node dist/cli.js doctor`
- 在 [GitHub Issues](https://github.com/cky008/cpe-dash/issues) 提问，附上版本号、安装方式和相关日志。**贴日志前先删掉密码、令牌、号码、短信内容和公网 IP。**
